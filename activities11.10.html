活动模块优化 · 可执行方案（讨论稿）

版本：v0.1 讨论稿　｜　日期：2026-11-10　｜　负责人：产品 

说明：本稿用于对齐范围、优先级和需求方向；标注「待确认」的内容在评审会上决定，确认后再出详细需求和原型。

一、背景与目标

1.1 现状问题

  • 会员同一时间只能有一个优惠钱包，进行中时不能参加其他活动，影响活动并行和复购。
  • 活动只有一种玩法（转本金领取，按比例送，有上限），没有存送、抽奖、签到等常用模板。
  • 活动和充值没有关联，无法做首存 / 次存 / 渠道加送等拉充值活动。
  • 不能按人群（名单、VIP 等级、标签、新注册）投放活动。
  • 没有活动预算控制，没有单活动的效果统计。
  • 风控已有大量检测和标签，但没有和活动领取、打码、处置联动。

1.2 目标

  1. 支持多活动并行（优惠队列），会员可随时退出并按进度结算。
  2. 补齐存送、梯度、抽奖、签到等活动模板，运营可通过后台配置上新活动。
  3. 活动可按人群精准投放，并有预算控制。
  4. 风控贯穿领取前、优惠中、提现时、事后四个阶段。
  5. 每个活动可量化评估成本和收益。

2.2 优先级定义

  • P0：底座和核心收入活动，其他功能依赖它，或上线即有风险必须同步。
  • P1：增强和管控，P0 上线后尽快跟进。
  • P2：锦上添花，视运营情况排期。

三、需求说明

第一期（P0）

R01 优惠队列【P0】

目标：会员可同时参加多个活动，按顺序进行。

现状：同一时间只能有一个优惠钱包，进行中时不能再领。

规则

  1. 每个会员 = 1 个「进行中」+ 多个「排队中」，队列暂不设上限。
  2. 按加入时间先后排队，先进先出。
  3. 加入队列时本金从主钱包扣除并锁定，不能投注、不能提款。
  4. 奖金和打码要求按加入时的活动规则计算并固定，之后活动修改或下架不影响已加入的记录。
  5. 当前优惠结束（打码完成、余额低于最低额、取消、到期、系统终止）后，自动开始下一个；打码要求和有效期从开始时计算。
  6. 只有「进行中」的优惠可投注和计打码。
  7. 排队中的记录可取消，本金全额退回，不发奖金、不收手续费。

后台：会员详情可查看该会员的队列（进行中 + 排队中）及历史。

前台：钱包页显示进行中和排队中的列表、排队锁定金额合计；活动页显示「进行中 / 排队中」。

待确认：队列后续是否需要设上限（防止大量本金长期锁定）。

R02 手动取消 / 到期结算【P0】

目标：会员可主动退出优惠，到期也不整笔作废，按进度返还应得部分。

规则

  1. 打码进度 = 已完成有效打码 ÷ 要求打码（最高 100%）。
  2. 结算金额 = 当前优惠余额 − 奖金 ×（1 − 打码进度）− 手续费，最低为 0。（公式待确认）
  3. 手动取消：可随时取消，取消前显示试算结果，二次确认；可收手续费（按活动配置，百分比或固定金额，可为 0）。
  4. 到期结算：同公式，不收手续费。
  5. 系统终止（见 R04）：同公式，不收手续费。
  6. 结算后按时间先后自动开始队列中的下一个。

后台：活动配置增加「取消手续费」。

前台：钱包页「取消」按钮 + 试算弹窗（当前余额、扣回奖金、手续费、实际返还）。

待确认：结算公式；返还到主钱包的金额是否需要打码。

R03 存款笔数识别【P0】

目标：支持首存、次存、三存活动。

现状：只区分首充。

规则

  1. 按会员成功到账的存款计数：第 1 笔 = 首存，第 2 笔 = 次存，第 3 笔 = 三存，可扩展到第 N 笔。
  2. 失败、取消、被拒的存款不计数；后台手动加款不计数。
  3. 按到账时间排序，不按提交时间。
  4. 不限支付方式。

后台：活动配置增加「存款序号」；充值订单显示「第 N 笔存款」。

R04 活动参与人员设定【P0】

目标：活动可按人群精准投放，排除风险人群。

现状：VIP 等级、会员标签已有；会员名单、注册天数条件需新增。

规则

  1. 创建活动时设置参与人群，可「指定」或「排除」：会员名单（支持导入）、VIP 等级、标签、注册 N 天内。
  2. 前台展示：
  • 指定人群内：显示活动；
  • 排除人群内：不显示、不能参加，系统自动发放的奖励也跳过；
  • 未登录：不展示限定人群的活动，不限人群的活动正常展示。
  1. 参加后不再符合条件（如命中排除名单或标签）时，活动自动终止：
  • 进行中的按 R02 结算，不收手续费；
  • 该活动排队中的记录，本金全额退回。

后台：活动配置增加「参与人群」设置。

待确认：条件变化的检测时机（实时 / 定时）。

R05 存送活动【P0】

目标：充值即参加活动，拉动首存和复充。

现状：活动和充值没有关联，只能转本金领取。

规则

  1. 后台新增「存送」活动类型，奖励可按比例或阶梯（见 R06），可配置存款序号（R03）、最低存款、打码倍数、适用游戏。
  2. 充值页显示会员可参加的存送活动 + 「不参加」，默认不参加；到账后该笔存款自动进入优惠队列（R01）。
  3. 到账时如不符合条件（活动结束、已参加过、不在人群内），按普通存款到账，并发站内信说明。
  4. 充值时未选择的，可在活动详情页补选：跳转优惠页面，金额输入改为下拉选择「符合条件且未投注的充值订单」。
  5. 每笔存款只能参加一个活动。

后台：活动管理新增存送类型；充值订单显示「参加活动」。

前台：充值页活动选择；活动详情页补选。

待确认：补选的时间限制（如到账后 N 小时内）。

R06 梯度奖励【P0】

目标：按金额区间设置不同奖励，提高大额充值意愿。

现状：只能配置「百分比 + 最高奖励金额」。

规则

  1. 奖励方式二选一：比例（现有）或梯度。
  2. 梯度按本金 / 存款金额区间配置，每档可设固定金额或比例，以及该档打码倍数。
  3. 区间不能重叠，按命中的档位计算。
  4. 适用于存送活动和普通领取活动。

后台：活动规则增加「梯度表」编辑。

前台：活动详情页展示梯度表。

R07 风控 · 领取前拦截 + 优惠期间限制【P0】

目标：活动上线即具备基础防套利能力。

现状：已有约 30 个风控检测（套优惠、领了就走、多账户、共用设备 / IP / 银行卡、对冲等）和会员标签，但未与活动联动。

规则

  1. 领取前：命中指定风险标签的会员不能参加（与 R04 排除标签打通）。
  2. 优惠期间：
  • 单注最高投注额（按活动配置，超出拒绝下注或该注不计打码，待确认）；
  • 低赔率投注不计打码（如体育赔率低于设定值）；
  • 对冲投注不计打码。

后台：活动配置增加「单注上限」「最低赔率」。

待确认：超过单注上限时是拒绝下注还是不计打码（拒绝下注需游戏平台支持）。

第二期（P1）

R08 活动预算设定【P1】

规则

  1. 每个活动可设总预算、每日预算、每日名额。
  2. 领取或加入队列时占用预算；取消、结算扣回的奖金释放回预算。
  3. 预算或名额用完自动停止领取，前台提示「已满员」，并发告警。

后台：活动配置增加预算字段，列表显示预算消耗。

R09 资金来源【P1】

目标：防止解锁资金反复领取优惠。

规则

  1. 主钱包余额按来源区分：存款、打码派奖、优惠解锁。
  2. 活动可配置「允许的本金来源」，参加时只能用允许来源的余额。
  3. 扣减顺序（投注、提款、参加活动）待开发评估后确定。

待确认：后台加款归哪一类；扣减顺序。工作量较大，需单独评估。

R10 VIP 周礼金 / 月礼金【P1】

现状：VIP 奖励已有升级、生日、每周救援金，没有周 / 月礼金。

规则

  1. 奖励配置新增「周礼金」「月礼金」，按 VIP 等级设置金额、打码倍数、有效期。
  2. 领取条件：如当周 / 当月存款或流水达到要求（可配置）。
  3. 符合条件后发放到奖励中心，会员手动领取。

R11 抽奖活动【P1】

现状：只有体验金红包（新会员一次，随机金额）。

规则

  1. 后台新增「抽奖」活动类型：抽奖条件、奖品（金额、概率、库存、打码倍数）、单人次数上限。
  2. 会员满足条件（如单笔存款满 X、当日打码满 X）获得抽奖次数。
  3. 通过浮窗或活动详情页抽奖；奖金发放到奖励中心。
  4. 接入活动预算（R08），预算用完只能抽到最低档或「谢谢参与」。

待确认：抽奖次数有效期；是否把体验金并入抽奖（建议抽奖稳定后再并入）。

R12 风控 · 提现时审核 + 事后处置【P1】

现状：已有提现流水检查和人工审核；风控只打标签，没有自动动作。

规则

  1. 提现审核页显示会员当前及近期参与的活动、打码进度、风控命中情况。
  2. 风险标签可配置自动动作：冻结优惠、禁止参加活动、扣回奖金，并通知客服。

R13 单活动统计【P1】

指标：领取人数、发出优惠、带来的充值、有效投注、GGR、净收益、成本率、风控命中人数、没收金额。

  • 净收益 = GGR − 优惠 − 返水
  • 成本率 = 优惠 ÷ GGR

待确认：「带来的充值」口径（存送关联的存款 / 领取后 N 天内的充值）。

第三期（P2）

R14 存款奖励（渠道加送）【P2】

规则

  1. 存款渠道可配置加送：比例或固定金额、享有条件、频率限制、打码倍数。
  2. 可与存送活动同时享有。
  3. 加送金额直接进钱包，奖励记录状态为「已领取」。
  4. 渠道加送计入全站成本率统计。

R15 签到活动【P2】

规则

  1. 后台设定签到周期、签到条件（当日充值或流水满足要求）、每日奖励、满签奖励。
  2. 前台展示签到入口、签到状态和奖励领取。

R16 全站成本告警【P2】

规则：全站成本率超过阈值（如优惠 > GGR 的 35%，可配置）时在群内告警。

待确认：告警群和处理人。

R17 后续规划

根据运营情况扩展竞猜、赛事、排名等活动模板。

五、风险

风险 说明 应对
工期 优惠队列、资金来源涉及钱包底层，改动大 先评估工期；资金来源可放到第二期

六、待决策事项汇总

  1. 优惠队列后续是否设上限
  2. 取消 / 到期结算公式；返还金额是否需要打码
  3. 参与人群条件变化的检测时机
  4. 存送补选的时间限制
  5. 超过单注上限：拒绝下注还是不计打码
  6. 资金来源：后台加款归类、扣减顺序
  7. 抽奖次数有效期；体验金是否并入抽奖
  8. 「带来的充值」统计口径
  9. 全站告警群和处理人
